# Software Engineering

This book is about making software understandable, testable, safe to change, and explainable to other people. It joins design principles, worked design patterns, testing, reviews, delivery, security, diagrams, and documentation into one sequence. The reference code is shown so you can question its assumptions, predict a failure, choose a useful check, and validate the result. The goal is judgment that remains useful when a tool generates the implementation.

## What you will be able to do

- Explain a design through its constraints, tradeoffs, and change boundaries.
- Design tests that can disprove a claim and distinguish test coverage from validation.
- Review, release, migrate, and maintain software with explicit compatibility rules.
- Apply security and authorization principles to concrete interfaces and failure modes.
- Use diagrams, decision records, runbooks, and written explanations with clear engineering vocabulary to make reasoning reviewable.

## Ways through this book

Read the parts in order for the full progression, or choose a route below and follow its prerequisites. Pause at the review questions before revealing worked answers.

- **Designing and testing:** [The Pragmatic Programmer](01-pragmatic-programmer/README.md), then [The Testing Mentality](03-testing/README.md), then [Coding and Design Patterns](04-design-patterns/README.md).
- **Maintaining and delivering:** [Code Review and CI](06-code-review-and-ci/README.md), then [Releases and Deprecation](07-releases-and-deprecation/README.md), then [Maintenance](08-maintenance/README.md).
- **Securing and explaining:** [Security](09-security/README.md), then [Authorization and Access Control](10-authorization/README.md), then [Diagramming with the C4 Model](11-diagramming/README.md), then [Documentation Writing](12-documentation/README.md).
- **Learning the team's vocabulary:** [Engineering Acronyms](13-engineering-acronyms/README.md), chapter 13, explains everyday terms through decisions, goals, reliability targets, and vendor work. Start here when those terms are unfamiliar.

## Before you start

You should be able to read and write small programs. [Programming and Algorithms](../programming-and-algorithms/README.md) develops language and algorithmic reasoning. [Systems Engineering](../systems/README.md), [Data Engineering](../data-engineering/README.md), and [AI Engineering](../ai-engineering/README.md) apply these practices to particular domains. [Worked Projects Across the Library](../../references/worked-projects.md) points to the case studies in those books.

[How to read these books](../../references/how-to-read.md) explains the shared first-principles, prediction, reasoning, testing, and validation method.
