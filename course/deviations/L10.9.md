## L10.9: the serve loop routes tool calls

`L10.9` now `upgrades` `rust/crates/tl-serve/src/server.rs` after `L10.7`
(the chain is L10.5, L10.7, L10.9; the snapshots are in
`course/ref/history/`). The chat route reads `tools`, `tool_choice`,
`response_format`, and `parallel_tool_calls` from the raw body with
`parse_tool_request` (so a schema's property order survives), strips them,
and hands the rest to L10.5's `parse_chat`. The prompt comes from
`render_prompt`; one `TokenIndex` per grammar pattern is built over the
model's vocabulary and cached. A request with a grammar runs on the engine
thread outside the batch, as the speculative path does: its own KV blocks
through `spec::RunnerTarget`, `constrained_sample` per token, and the
request's own generator. In `auto` mode decoding is free until the output
contains `<tool_call>`, then the constraint starts in the state the bytes
after it lead to. A grammar that is complete with no token left to allow (a
vocabulary without EOS) ends the answer with `stop`. With tools and a
`tool_choice` other than `none`, the text goes through `ToolParser` into a
`tool_calls` message or stream deltas, and `finish_reason` is `tool_calls`
when the answer called a tool. Per-sequence masks inside `Engine::step`
(constrained requests in the batch) are left to a later upgrade.

`deps` gains `L10.7` (the serve loop taken over). `used_by` is `obs.02`, the
call site `server.rs` already has through `L10.7`, which an upgrading module
inherits (DESIGN 3.4). `ag.01` and `MS-agent` read `tool_calls` over HTTP
and keep `L10.9` in `reading`.

`L10.5`'s test `errors_use_the_openai_shape` asserted that `tools` is 422,
which stops being true once this module takes the server over, and
`ol check L10.9` runs L10.5's tests as a regression. The case now sends
`response_format` `json_schema`, which is 422 `unsupported_parameter` with
`param` `response_format` before and after L10.9.
