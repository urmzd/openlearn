## Comments

**C1, section 4 (options).** The draft compared A and C only, and its TPOT row for A said "fine" with no number. Recomputed with the draft's own speeds: a 512-token chunk on 4 threads is 512 / 4,000 = 128 ms inside one step, so TPOT p95 for A is about 143 ms, not "fine". Change: add B, put a number in every cell, and state `prefill_chunk`; with 128-token chunks A is 47 ms. *Closed:* the table now has three options and numbers in every cell.

**C2, section 3 (interfaces).** Metrics scraping and rule loading are an interface too: the draft did not say that Prometheus only loads `PrometheusRule` and `ServiceMonitor` objects labelled `release: observability` (`contracts/helm/observability.md`). A missing label is silently ignored, which is exactly how alerts go missing. *Closed:* added to the telemetry row.

**C3, section 5 (failure modes), challenge.** The draft said "a dead gateway shows up as availability burn". It cannot: the 5xx ratio is computed from `http.server.request.duration`, which the gateway itself records, so a dead gateway produces no 5xx at all and the availability alert stays quiet. Question for observability: who probes from outside? *Closed:* the row now says so, and open question 2 owns the probe.

**C4, section 5, challenge.** In-flight streams on a killed decode pod already returned `200 OK`; ending them with an SSE `error` event is right, but those failures are invisible to the 5xx-based availability SLI too. Change: count stream errors (`tl.gateway.requests{code="stream_error"}`) and include them in the availability ratio, or say explicitly that the SLI excludes them. *Closed:* section 6 bounds the cost (about 5 streams per kill) and open question 2's probe covers the gap; the SLI definition stays as the contract fixes it.

**C5, section 6 (capacity), recomputed.** KV bytes per token: 2 x 30 x 3 x 64 x 2 = 23,040 B. Holds. The draft wrote the pool as 2048 x 23,040 = 47 MB, forgetting the 16 tokens per block; the right figure is 754,974,720 B (720 MiB), which changes the memory total from "about 3 GiB" to about 4.8 GiB. Still fits the 12 GiB node. Little's law: 4 x (0.5 + 31 x 0.06) = 9.44 in flight. Holds. Error budget: 0.005 x 30 x 24 x 60 = 216 minutes, and 14.4 / 720 = 1/50 of it per fast-burn hour. Holds. Change: fix the pool size and give the prefill engine a smaller pool (512 blocks), since it holds blocks only until `Release`. *Closed.*

**C6, section 7 (rollout).** The draft said "helm rollback" and nothing about state. The ledger is SQLite on a hostPath: two gateways during a rolling update would write one file, and a schema rollback loses rows. Change: `Recreate` for the gateway with its outage counted against the budget, forward-only migrations with a backup, and the readers-first order for KV v2. *Closed:* section 7 now has all three.

## Decision

**Approve with changes**, all six comments applied in the current version. Open questions 1 and 2 must be answered before MS-prod is claimed (owners in section 8); 3 and 4 are accepted risks until Pass 11.
